# 司机轨迹坡度分析服务

输入经纬度轨迹,基于本地 30m DEM 计算里程、爬坡/下坡/平路占比、累计爬升/下降、最大坡度等指标。

> **部署**:桌面版(Mac .app / Windows .exe,用户免装 Python)见 [doc/桌面版打包说明.md](doc/桌面版打包说明.md);整包迁移与服务器部署见 [doc/部署说明.md](doc/部署说明.md)。

## 数据源

**Copernicus DEM GLO-30**(30m 分辨率,2022 年发布):
- AWS 公开数据桶 `s3://copernicus-dem-30m/`,**无需任何账号**,直接 HTTP 下载
- 1°×1° 瓦片,COG 压缩 GeoTIFF,平均 10~25MB/片(平原小、山区大)
- 数字表面模型(DSM),含植被和建筑,服务端已做高程平滑抑制噪声
- 行政边界来自阿里 DataV(用于按省过滤瓦片),缓存于 `data/boundaries/`

数据量参考(以实际 dry-run 输出为准):

| 范围 | 瓦片数 | 体积约 |
|---|---|---|
| 全国,默认排除 adcode 540000、460000 两省 | 989 | 15~25 GB |
| 单个中东部省份 | 20~80 | 0.3~1.5 GB |

> 排除逻辑按省级边界精确判断瓦片中心点,不会误删邻省交界区域。

## 快速开始

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 1. 预览要下载的瓦片(不下载)
.venv/bin/python src/download_dem.py --dry-run

# 2. 下载(约 15~25GB,建议 nohup 后台跑,支持断点续传,中断后重跑即可)
nohup .venv/bin/python src/download_dem.py --workers 16 > download.log 2>&1 &

# 3. 启动服务(浏览器打开 http://127.0.0.1:8107;Windows 把 .venv/bin 换成 .venv\Scripts)
.venv/bin/uvicorn --app-dir src server:app --host 0.0.0.0 --port 8107

# 4. 测试(另开终端)
.venv/bin/python src/test_client.py    # 命令行端到端测试
```

## 网页界面

界面设计令牌与组件规范参考 `wms表格转换2` 项目(Excel 绿主题);布局骨架为专业 GIS 工作台样式(参考 GeoLibre):**顶栏工具条 + 左侧停靠分析面板 + 地图占满 + 底部状态栏**,整页不滚动、面板内部滚动。

- 顶栏:文件上传、坐标系 / 里程来源、高级参数(折叠)、面板开关、帮助
- 左侧停靠面板(可整栏收起):行程信息(司机 / 车辆 / 载重 / 耗油补录)→ 核心指标 → 复盘摘要 → 坡度分布 → 关键路段(点击定位)
- 地图列:地图占满剩余空间;下方可停靠**高程剖面**与**轨迹明细**面板(状态栏开关,明细默认点少时展开)
- 状态栏:鼠标高德坐标(等宽字体)、行程摘要(里程 / 爬升 / 油耗 / 质量)、剖面 / 明细 / 面板开关
- 导出:明细 CSV(全量原始点)与行程报告 CSV(行程信息、指标、数据质量、关键路段、参数、边界声明)

浏览器打开服务地址即可,无需安装任何前端依赖(Leaflet 已本地化,可离线部署):

- 上传 xlsx / csv 轨迹文件,自动按表头识别「经度 / 纬度 / 记录时间」列(兼容 lon/lng/lat/time 等命名),有时间列时自动按时间升序重排
- 底图默认为**天地图地形**,可切换 Esri 地形、高德路网 / 高德卫星。轨迹按坡度三色着色:红=爬坡、蓝=下坡、灰=平路;悬停路段显示该段距离与平均坡度。地形图为 WGS-84、高德图为 GCJ-02,切换底图时轨迹自动按对应坐标系落图,坐标读数始终显示高德坐标
- 点击轨迹点弹窗显示该点**高德经纬度**、高程、坡度;鼠标在地图任意位置移动,左下角实时显示高德坐标
- 右侧指标卡片:总里程、爬坡/下坡/平路里程与占比、累计爬升/下降、最大坡度、高程范围
- 底部高程剖面图(与地图联动:悬停剖面在地图上高亮对应点)
- 轨迹点明细表(仅原始记录,含经纬度、高程、坡度、累计里程)

可调参数(页面顶部):

| 参数 | 默认 | 说明 |
|---|---|---|
| 坐标系 | 高德 GCJ-02 | 上传高德/国内平台轨迹保持默认;WGS-84 原始 GPS 选第二项。服务端采 DEM 前会自动 GCJ-02→WGS-84 转换 |
| 里程来源 | 里程表列(优先) | 文件含「里程」累计列(车辆里程表)时,总里程与坡度分母用里程表增量,最接近真实行驶距离;无该列或列无效时自动回退 GPS 折线。也可强制指定 |
| 坡度阈值 | 2 % | 大于阈值计爬坡,小于 -阈值计下坡 |
| 沿线加密 | 0(关) | 相邻点间距超过该值时按直线插点采 DEM,详见下节 |
| 平滑窗口 | 150 m | 高程序列移动平均,抑制 DSM 树冠/建筑噪声 |

**为什么 GPS 折线里程比平台显示的小**:相邻 GPS 点的直线(大圆)距离之和必然小于沿道路的实际行驶距离——点距越大、道路越弯,差得越多(例:点距 ~500m 的高速轨迹,GPS 折线 2183.6 km vs 里程表 2345.7 km,差 ~7%)。响应中同时返回 `gps_chord_m`(GPS 折线)与 `total_distance_m`(按所选来源),便于对账。平台统计值若与里程表仍有出入,属于平台内部口径(路径匹配、统计边界等),以车辆里程表为准。

体积更小的替代方案:

```bash
# 只下载轨迹实际覆盖的省份(参数支持省名或 adcode)
.venv/bin/python download_dem.py --only-provinces 110000 130000 140000

# 自定义排除名单(默认 540000 460000)
.venv/bin/python download_dem.py --exclude 540000 460000
```

**按需下载(默认开启)**:请求覆盖本地缺失的 DEM 瓦片时,自动从 AWS 拉取(单瓦片 20~50MB,首次分析慢几秒到几十秒)。并发请求自动去重;下载中断留下的坏文件会在下次请求时自动清理重下。要关闭:

```bash
AUTO_DOWNLOAD=0 .venv/bin/uvicorn --app-dir src server:app --host 0.0.0.0 --port 8107
```

## API

### POST /analyze

```json
{
  "points": [[116.05, 40.31], [116.06, 40.32], "..."],
  "coord_system": "wgs84",
  "grade_threshold": 0.02,
  "smooth_window_m": 60
}
```

| 字段 | 说明 |
|---|---|
| points | 轨迹点,`[lon, lat]` 数组或 `{"lon":..,"lat":..}` 对象数组,按时间顺序,至少 2 个 |
| coord_system | `wgs84` 或 `gcj02`。**国内车机/平台回传坐标多为 GCJ-02,偏移 50~500m,山区会导致采错高程,务必按实际情况传** |
| grade_threshold | 坡度阈值,0.02 即 2% |
| smooth_window_m | 高程平滑窗口(米),默认 150,0 关闭 |
| densify_m | 沿线加密步长(米),默认 0 关闭;点距稀疏时可设 30(直线近似,见「稀疏轨迹」一节) |

另有 `POST /analyze/file`(网页界面使用):multipart 上传 xlsx/csv + 同名表单参数,自动识别列、按时间排序、沿线加密,返回指标 + 逐点明细(坐标、高程、坡度、累计里程,`interp` 标记插值点)。

响应示例:

```json
{
  "total_distance_m": 35006.5,
  "climb_distance_m": 14622.7,
  "descent_distance_m": 18610.9,
  "flat_distance_m": 1772.9,
  "climb_ratio": 0.4177,
  "descent_ratio": 0.5316,
  "flat_ratio": 0.0506,
  "total_ascent_m": 2619.5,
  "total_descent_m": 2954.2,
  "max_climb_grade": 0.6595,
  "max_descent_grade": 0.3976,
  "min_grade": -0.3976,
  "elev_min_m": 400.4,
  "elev_max_m": 1001.9,
  "point_count": 80,
  "nan_point_count": 0
}
```

### GET /health

返回已加载瓦片数、覆盖范围、是否开启自动下载。

## 指标口径

- **坡度** = 相邻轨迹点高差 ÷ 距离(公路工程口径),`>阈值` 计爬坡、`<-阈值` 计下坡,±阈值内为"平路(±2%)"(指坡度很小,并非无坡);**高程缺失路段单独计为"无高程",不计入平路**
- **每百公里爬升** = 累计爬升 ÷ 总里程 × 100,用于不同长度行程比较爬升强度
- **累计爬升/下降** = 相邻点正/负高差累加(已剔除 <1m 静止点;GPS 与里程表两种距离来源对静止段取舍略有差异)
- **最大坡度** 按 **≥100m 滑动窗口**计算;DEM 为 DSM(含树冠/建筑),桥梁/隧道附近可能跳变,极值仅供参考
- **连续长坡** = 同类坡度路段连续合并(≥200m),按长度取前 5
- **时间统计**:总时长、停留(GPS 不动,**不代表怠速**)、≥30 分钟记录断点
- **数据质量**:有效高程覆盖率、未知里程、断点、平均点距综合评级(良好 / 可用 / 需注意)

## 边界声明(刻意不做的事)

- 未填实际耗油时不展示任何估算油耗;**加油量 ≠ 本趟消耗**(需期初/期末油量或连续加满区间推算)
- 只有整趟耗油时不做分路段油耗摊派;GPS 停留不推断怠速
- 不做司机评分 / 排行榜 / 自动判责——高程用于解释油耗差异,不用于直接评价司机

## 稀疏轨迹(重要)

平台按 1~2 分钟抽稀导出的轨迹(点距公里级)无法直接支撑 2% 阈值的坡度分析:

- **不加密**:两点之间的起伏全部漏掉,结果是被严重低估的下限(例:259 km 行程算出 98.7% 平路、爬升 554 m)
- **沿线加密**:相邻点按直线插点采 DEM。直线不是道路线形——会穿过道路绕开的山体、跨过桥下水面,结果是偏高的上限(同一条轨迹算出爬升 5313 m、最大坡度 57%,明显失真)

界面在点距 >200m 时会给出提示。**可靠做法**(按优先级):

1. 拿到 ≤100m 间距(约 ≤10s 一个点)的原始轨迹再分析;
2. 用高德 Web 服务「轨迹纠偏」(v4/grasproad)或「驾车路径规划」(v5/direction/driving)把稀疏点还原成道路线形(返回的密集 GCJ-02 折线),再把这些点以 `coord_system=gcj02` 调 `POST /analyze` —— 服务端会沿真实道路采 DEM,指标即准确。此步需要自行申请高德 Web 服务 key;
3. 只看累计爬升等粗指标时,可参考"不加密(下限)~ 加密(上限)"的区间。

## 生产部署(systemd 示例)

```ini
# /etc/systemd/system/grade-api.service
[Unit]
Description=Driver trajectory grade analysis API
After=network.target

[Service]
WorkingDirectory=/opt/grade-api
ExecStart=/opt/grade-api/.venv/bin/uvicorn --app-dir /opt/grade-api/src server:app --host 0.0.0.0 --port 8107 --workers 4
Environment=AUTO_DOWNLOAD=1
Restart=always

[Install]
WantedBy=multi-user.target
```

注意:`--workers >1` 时每个进程独立持有 DEM 文件句柄,内存占用可忽略。主要成本是磁盘空间和首次下载带宽;若国内服务器访问 AWS 较慢,可先在海外机器下载后 rsync 同步 `data/dem/` 目录。
